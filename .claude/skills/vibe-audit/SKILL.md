# vibe-audit: аудит безопасности вайбкод-проекта

## Что делает
Детерминированный сканер + live-проверка своего сайта + чек-лист + твоя голова поверх.
Находит типовые дыры вайбкода и выдаёт отчёт «проблема → фикс» с главной цифрой находок.

## Принципы (обязательно)
1. **Только чтение и только свои ресурсы.** Ничего не менять. Live-проверку запускать
   ТОЛЬКО против домена, которым владеет пользователь — скрипт сам спросит подтверждение.
2. **Секреты не цитировать.** Скрипты маскируют найденное; ты тоже никогда не выводишь
   полное значение ключа.
3. **Формат «проблема → фикс».** Никогда не объясняй, как эксплуатировать находку,
   не пиши пейлоады, не сканируй чужие домены — это не входит в задачу и не нужно.
4. Найден живой ключ → первым пунктом ответа «перевыпусти его сейчас».

## Порядок работы

### Шаг 1. Статический сканер (код и конфиги)
```bash
python3 scripts/audit.py /путь/к/проекту --report vibe-audit-report.md
```
Чистый python3, без зависимостей. Ловит: секреты 9+ сервисов, .env в git, ключи во
фронтенде, CORS *, debug, eval, SQL-инъекции, JWT alg:none, отсутствие rate limit,
AI-эндпоинты без авторизации (cost bomb), LLM-вызовы без max_tokens, роль из клиента,
IDOR-подозрения, JWT без expiry, открытые Firebase-правила, дефолтные пароли и
проброшенные порты БД в docker-compose, уязвимые npm-зависимости.

### Шаг 2. Проверка заголовков задеплоенного сайта (опционально, только свой домен)
Если у пользователя есть развёрнутый сайт и это ЕГО домен, можно проверить публичную
гигиену: правильно ли выставлены security-заголовки и не отдаёт ли сервер по ошибке
служебные файлы. Это то же, что делает публичный сервис securityheaders.com — обычные
GET-запросы к своему сайту, не сканирование уязвимостей и не атака.
```bash
python3 scripts/livecheck.py https://его-сайт.com
```
Проверяет: security-заголовки, флаги кук, и не открыты ли по ошибке .env / .git / дампы.
Скрипт требует подтверждения владения — не обходи это за пользователя без явного
«да, это мой домен». Чужие домены проверять нельзя.

### Шаг 3. Ручной проход (то, что regex не умеет)
Просмотри код и добавь своими секциями: эндпоинты без auth, отсутствие валидации ввода,
auth «на доверии», секреты в логах, отсутствие проверки владения ресурсом.

### Шаг 4. Чек-лист перед деплоем
Покажи пользователю `checklist.md` — там непроверяемое сканером: spending limits в
консолях AI, 2FA, RLS, бэкапы, права сервис-аккаунтов. Пройдитесь по нему вместе.

### Шаг 5. Отдай результат
- Главная цифра: «N находок: X критичных / Y важных / Z на проверку».
- Оба отчёта + топ-3 «чини прямо сейчас».
- Предложи починить по списку (но не чини сам без просьбы).

## Ограничения — говори о них честно
Это линтер типовых ошибок + внешний чек заголовков, а не пентест. Не проверяет логику
авторизации в глубину, инфраструктуру, права в облачных консолях. Чистый отчёт ≠
безопасное приложение. Для прода с деньгами/персданными — нужен живой специалист.
