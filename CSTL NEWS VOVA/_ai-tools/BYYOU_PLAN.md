## 🔴 РОЗВІДКА 07.08 ПЕРЕВЕРНУЛА ПЛАН. Читай перш ніж щось робити

Чернетка кроків (нижче, в архівному блоці) виходила з того, що дані **недоступні** і
їх треба відкривати. Читання коду показало інше.

### 1. Публічне читання імен і фото ВЖЕ Є — і краще, ніж відкрита RLS

`scripts/supabase_avatars_public.sql` → `get_avatars(uids uuid[])`, `SECURITY DEFINER`,
grant для `anon` і `authenticated`. Віддає **рівно** `uid, name, avatar_url`.
Поруч — `get_public_profile(p_uid)` (6 несекретних полів для картки профілю).

➡️ **Питання №1 до Вови («робимо імена і фото публічно читабельними?») закривається
відповіддю «вже зроблено».** Вова сказав «Так» — і це підтверджує чинну конструкцію.
🛑 **RLS на `profiles` НЕ відкривати.** Вузький RPC уже дає рівно те, що треба, і при
цьому фізично не може віддати телефон, пошту чи дату народження. Відкриття таблиці
розширило б поверхню без жодної нової користі.

### 2. СПРАВЖНІЙ корінь — вічний кеш у памʼяті, а не доступ

`src/core/supabase.js:413-414`:
```
const _avatarCache = new Map();   // uid -> url
const _nameCache   = new Map();   // uid -> живе імʼя
```
`fetchAvatars()` бере **лише невідомі** uid: `.filter(u => u && !_avatarCache.has(u))`.
Тобто дізнались імʼя один раз — тримаємо його **до кінця життя вкладки**. Негативи
(«профілю нема» = `''`) кешуються так само назавжди.
Другий поверх того самого: `hydrateAvatars`/`hydrateNames` ставлять вузлу
`data-av-done` / `data-name-done` і більше до нього не повертаються.

➡️ Це **дослівно** пояснює слова Вови «приходиться закрити додаток повністю і зайти»:
повне закриття скидає памʼять — інших способів очистити ці дві `Map` у коді немає.

### 3. Міграція старих розмов НЕ потрібна

Заморожені `threads.buyer_name` / `author_name` уже перекриваються живим імʼям:
рядок списку розмов (`board-chat.js:777`) і шапка чату (`:141`) несуть `nameUid(...)`,
а `hydrateNames` підміняє текст. Плюс у базі є тригер `sync_profile_denorm`
(`scripts/supabase_identity_sync.sql`), який оновлює денормалізовані копії.
➡️ **Крок 8 чернетки знято.** Лишається лише звірити, що тригер справді накатано.

### ⚠️ Обмеження цієї сесії
MCP Supabase **не авторизований** — перевірити RPC і тригери прямо на проді з чату
неможливо. Це нічого не блокує (міграцій потік не потребує), але **крок 3 — звірка
руками Вови**, а не «вважаємо що там усе гаразд».
