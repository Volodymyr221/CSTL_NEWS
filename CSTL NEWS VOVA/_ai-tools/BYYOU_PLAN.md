# BYYOU_PLAN — стан потоку /byyou (CSTL)

**Статус:** `active`
**Гілка:** `claude/startuem-sq0h2w`
**Ціль:** дзвіночок сповіщень «Стрічки» працює надійно на будь-якому рівні — як у справжніх додатках: тап по дзвіночку одразу питає дозвіл, стан дзвіночка чесний, а сповіщення про новий пост доходить підписникам ЗАВЖДИ (незалежно від того, чи живий браузер автора).

> Попередній завершений потік: 2026-07-24 uploads → `BYYOU_ARCHIVE_2026-07-24_uploads.md`.

## Діагноз (з реального коду, не з пам'яті)
| # | Проблема | Де |
|---|----------|-----|
| 1 | Дозвіл питається ПІСЛЯ `await` запису в базу → жест користувача «згорає», на iOS вікно дозволу не з'являється | `feed.js toggleBell` → `registerFeedPushDevice` |
| 2 | Дзвіночок бреше: горить «увімк.» навіть коли дозвіл відхилено / push недоступний | `feed.js toggleBell` |
| 3 | Пристрій реєструється лише в мить тапу; протермінована підписка не поновлюється; інші пристрої не реєструються | `feed.js` (нема self-heal) |
| 4 | Сповіщення шле браузер автора — закрив додаток / пост із адмінки → не піде ніколи | `feed.js:923 notifyNewPagePost` |
| 5 | Клік по сповіщенню при відкритому додатку лише фокусує вікно, `url` ігнорується | `sw.js notificationclick` |
| 6 | Помилка Edge-функції нікуди не йде (`console.warn`) | `supabase.js notifyNewPagePost` |
