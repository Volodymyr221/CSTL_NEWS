# Claude Starter Kit — готовий набір правил, скілів і хуків для Claude Code

**Що це.** Робоча система розробки з Claude, знята з живого проєкту і очищена від його
специфіки. Не опис і не приклад — **самі файли**. Розпаковуєш, копіюєш у свій репозиторій,
відповідаєш на 10 питань — і Claude працює за цими правилами.

**Чого тут НЕМА.** Чужого коду, чужих даних, чужого проєкту. Тільки методологія:
правила, скіли (skills — команди `/назва`), хуки (hooks — автоматичні сторожі), шаблони документів.

---

## Швидкий старт (3 хвилини)

1. Розпакувати архів.
2. Відкрити свій репозиторій у Claude Code.
3. Скинути Claude два файли — `INSTALL_FOR_CLAUDE.md` і `CLAUDE.md` — і написати:
   > **«Прочитай INSTALL_FOR_CLAUDE.md і встанови цей набір. Файли лежать у папці starter-kit.»**
4. Claude поставить **10 питань одним списком** (назва проєкту, як звертатись, бойова гілка,
   стек тощо). Відповідаєш — і він усе розкладає по місцях сам.

Далі в роботі: `/start` на початку кожного чату · `/finish` наприкінці · `/fix` на баг ·
`/audit` на перевірку · `/flow` на велику задачу.

## 8 хуків — що вони реально роблять

| Хук | Коли спрацьовує | Що робить |
|---|---|---|
| `pre-edit-read-check.js` | перед правкою файлу | **БЛОКУЄ** правку файлу, який Claude не читав у цій сесії |
| `cache-name-reminder.sh` | після правки коду/стилів | нагадує підняти версію кешу і дає готове значення з поточним часом |
| перевірка синтаксису | після правки `.js` | одразу проганяє `node --check`, результат видно в тому ж ході |
| `context-warning.sh` | на кожне твоє повідомлення | попереджає при 80% / 90% заповнення контексту |
| `session-git-sync.sh` | старт/відновлення сесії | `git fetch` + гучне «локальна гілка відстає від сервера» |
| `flow-push-lock.js` | перед будь-яким `git push` | у режимі `/flow` **БЛОКУЄ публікацію**, поки ти не сказав слово-дозвіл |
| `flow-context-guard.sh` | спроба завершити хід | при ≥75% контексту не дає тихо вийти без збереження точки зупинки |
| `token-guard.js` | навколо викликів агентів | один дорогий виклик > порогу → **пауза всієї сесії** до твого підтвердження |

Усі **fail-open**: якщо сам хук зламався — сесія працює далі. Блокують лише там, де ціна
помилки висока.

## Що дає ця система на практиці

| Проблема | Що її закриває |
|---|---|
| Claude правит файл «по памʼяті» і ламає код | хук блокування правки без читання |
| «Готово, запушив» — а насправді помилка | правило «✓ тільки після коду 0» + перевірка синтаксису хуком |
| Наступна сесія не знає, що робилось раніше | живий журнал + `SESSION_STATE.md` + підсумок при `/finish` |
| Недороблене потрапляє в прод | двогілковий потік: гілка → PR → бойова, тільки через `/finish` |
| Claude «почистив» код і зламав робочу фічу | правило №9 «не чіпай те, про що не просили» |
| Контекст закінчився посеред великої задачі | сторож 75% + `FLOW_PLAN.md` з точкою зупинки |
| Один агент спалив купу токенів | токен-запобіжник із паузою сесії |
| Задачі губляться між чатами | `TASKS.md` як єдине джерело істини |

## Головне, якщо читати нічого більше

> Це не інструмент, а **дисципліна**: не чіпати код без дозволу, не правити непрочитане,
> не звітувати про неперевірене — і записувати **причину** кожного рішення туди,
> де її знайде наступна сесія.

Усе інше — механіка, яка це підпирає.
