# /finish — Завершити сесію і опублікувати (мердж робочої гілки в бойову)

Виконуй кроки по порядку. Не пропускати жодного.

---

## 🔴 Крок 0 — Живий журнал сесії
Журнал `_session-log/<роль>-<дата>.md` ведеться ВСЮ сесію (створюється у `/start`).
На фініші: переконайся, що він існує і повний. Відстає — **допиши зараз** усе, що памʼятаєш
(файли, PR, деплої, рішення, інциденти, глухі кути). Крок 8 генерується З ЖУРНАЛУ, не з памʼяті.

## Крок 1 — Час
`date`. Результат потрібен для версії кешу.

## Крок 2 — Версія кешу (якщо в проєкті є Service Worker)
Формат `<префікс>-YYYYMMDD-HHMM`. **Не вигадувати час** — брати з Кроку 1.
**Виняток:** змінювались ТІЛЬКИ `.md` або `.claude/` — не чіпати.

## Крок 3 — Перевірка
`node --check <кожен змінений .js>` + прогін стендів (`npm test`, якщо є).
Помилка — **СТОП**. Виправити, тільки тоді далі.

## Крок 4 — Документація
- **ЗАВЖДИ:** `docs/_ai-tools/SESSION_STATE.md` — дата, що зроблено, відкриті задачі.
- Змінилась структура файлів → таблиця «Файлова структура» в `CLAUDE.md`.
- Змінилась архітектура → `docs/ARCHITECTURE.md`.
- Закрито баг → `docs/BUGS.md` (перенести у «Закриті» + дата + коміт + чим доведено).

## Крок 5 — Гілка
`git branch --show-current`. Бойова → Крок 6А. Інша → Крок 6Б.

## Крок 6А — Прямий пуш (рідко, тільки якщо вже на бойовій)
```
git add <конкретні файли — НЕ "git add .">
git commit -m "<тип>(<зона>): опис"
git push -u origin <бойова>
```

## Крок 6Б — Робоча гілка → PR → merge

**6Б.0 Синхронізація з бойовою (проти конфліктів і затирання):**
```
git fetch origin <бойова>
git merge origin/<бойова> --no-edit     # конфлікти вирішувати ВРУЧНУ, ніколи -X theirs
node --check <змінені .js>              # після злиття код має бути валідний
```

**6Б.1 Коміт і пуш:**
```
git add <конкретні файли>
git commit -m "<тип>(<зона>): опис"
git push -u origin <поточна-гілка>
```

**6Б.2 Створити Pull Request** (запит на злиття) через GitHub. Запамʼятати номер.

**6Б.3 Merge — метод `squash`** (усі коміти гілки стають одним).

## Крок 7 — Перевірка публікації
Через ~3 хв індикатор версії має змінити число. Не змінився → деплой не пройшов:
```
git commit --allow-empty -m "ci: retrigger" && git push origin <бойова>
```

## Крок 8 — 🧠 ПІДСУМОК ДЛЯ ЗОВНІШНЬОГО КОНТРОЛЕРА — ОБОВʼЯЗКОВО

> Власник веде «другий мозок» (окремий застосунок, який цей Claude НЕ бачить). Туди
> вставляється підсумок кожної сесії.
> **🔴 ВИДАВАТИ ОДНИМ суцільним блоком коду** — щоб скопіювати за один раз.

**Джерело — ЖИВИЙ ЖУРНАЛ + git-історія сесії. НЕ реконструювати з памʼяті.**
**Вичерпність важливіша за стислість** — читає аналітик, не людина. Довжина не обмежена.
Не «основне» — **ВСЕ**: кожен файл/функція/PR/деплой поіменно · кожне рішення + **ЧОМУ** ·
усе обговорене навіть невтілене · що НЕ спрацювало і чому · інциденти · хронологія ·
дослівні слова власника.

```
Підсумок сесії <ПРОЄКТ> [РРРР-ММ-ДД] (гілка […]):

🗂️ Зона: над чим працював
🔧 Що зроблено (код/файли): конкретні зміни
💬 Що обговорили (навіть якщо не робили)
🎯 Ключові рішення + ЧОМУ саме так
❌ Що не спрацювало (щоб не повторювати)
🗣️ Рішення власника (прямі цитати)
⏸️ Відкладене
🔄 Конфлікти/суперечності/відкати
⚠️ Інциденти (чесно)
👁️ Спостереження: як власник працював цю сесію
🔓 Відкриті питання
➡️ Наступний крок
📊 Версія/кеш
🌿 Гілка + діапазон комітів
```
В кінці блоку — рядок **«Запиши у brain.»**
