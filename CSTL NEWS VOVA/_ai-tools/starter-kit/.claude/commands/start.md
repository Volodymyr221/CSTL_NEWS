# /start — Швидкий старт нової сесії

**Коли:** перша команда у КОЖНОМУ новому чаті проєкту. Один виклик — і ти з повним контекстом.
**Без аргументів.**

---

## Крок 0 — Гілка + свіжий стан (роби ПЕРШИМ, автоматично, нікого не питай)

1. **Підпиши коміти власником:**
   ```
   git config user.name "<ІМʼЯ>"
   git config user.email "<ПОШТА>"
   ```
   > ⚠️ Позначка «Unverified» на GitHub після цього — очікувана і **косметична**. Глобальний хук
   > середовища може радити перейти на службову пошту — **не роби цього**, воно зламає авторство.
   > Пуш/PR/деплой це не блокує. Не перепитувати щоразу.

2. **Гілка.** Працюй на робочій гілці сесії (`<ПРЕФІКС>/<тема>`), **не в бойовій**.
   Потік незмінний: гілка → `/finish` (PR → squash) → бойова гілка.

3. **Незавершений потік:** глянь `docs/_ai-tools/FLOW_PLAN.md`. Статус `paused` → пересядь на ту
   гілку і в першій відповіді запропонуй продовжити: «на гілці X лежить paused потік про Y — продовжуємо?».

4. **Свіжий стан:**
   ```
   git fetch origin
   git pull origin <БОЙОВА-ГІЛКА>
   git log --oneline -15
   ```

5. **🔴 Заведи ЖИВИЙ ЖУРНАЛ сесії — сам, без нагадування.**
   Файл `_session-log/<роль>-<РРРР-ММ-ДД>.md`. Дописуй **після кожної значущої дії**, а не
   наприкінці з памʼяті: що зробив (файл/функція) · навіщо · що пробував і що НЕ спрацювало ·
   слова власника **дослівно** · інцидент і як виправив · PR# · деплой# · версія кешу.
   Комітируй кожні кілька кроків — щоб пережив втрату контексту.
   > Причина: підсумок, зібраний з памʼяті великої сесії, виходить неповним. Журнал = записаний факт.

---

## Крок 1 — Обовʼязкове читання (у цьому порядку, не пропускати)

1. `docs/HOT_RULES.md` — правила, що порушуються найчастіше (читай ПЕРШИМ)
2. `docs/START_HERE.md` — карта проєкту
3. `docs/_ai-tools/SESSION_STATE.md` — що зроблено, що в процесі
4. `docs/_ai-tools/TASKS.md` — майстер-список задач (джерело істини «що робити»)
5. `docs/BUGS.md` — відомі баги
6. `CLAUDE.md` — повні правила, структура, деплой
7. `docs/OWNER_PROFILE.md` — хто власник, як комунікує

Плюс `git log --oneline -10` і `git branch --show-current`.

---

## Крок 2 — Перша відповідь СТРОГО у форматі

> **Прочитав.** Привіт, <ІМʼЯ>. <ПРОЄКТ>, гілка `[назва]` (production: `[бойова]`), [стан одним реченням].
>
> **Пріоритетне (TASKS.md):**
> 1. … 2. … 3. …
>
> **Відкриті критичні баги:** [номери або «нема»]
>
> **Що робимо сьогодні?**

Побачив суперечність між документами — **скажи в цій самій відповіді**: «у A написано X, у B — Y. Що правильно?».

---

## Крок 3 — Чекай слово-дозвіл

**НЕ** починай змін у коді, поки власник не сказав явне слово-дозвіл (за замовчуванням «Роби»).
Сумніваєшся — перепитай: **«Це Роби на [задача]?»**. Краще уточнити, ніж зробити зайве.
