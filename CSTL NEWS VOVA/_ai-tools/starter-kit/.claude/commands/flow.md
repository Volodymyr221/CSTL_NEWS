# /flow — Напівавтономний режим

## Що це
Claude отримує ціль, планує 10-15 кроків і виконує потоком, зупиняючись лише на контрольних
точках. Власник контролює **результат**, не кожен крок.
Стан потоку — `docs/_ai-tools/FLOW_PLAN.md`.

## Коли
Великі цілі (≥3 файли або ≥1 година). **НЕ для дрібниць** (<30 хв) — там звичайний діалог або `/fix`.

## Команди
`/flow <ціль>` — новий потік (план → «ок» → виконання) · `/flow` — продовжити незавершений.

## Режим глибокої роботи (читати перед Фазою 0)
Думай широко. Копай глибоко. Будуй системні рішення. Помічай неочевидне. Не дій наосліп.
Перевіряй. Не будь наївним. Дивись наперед.

## Дві брами
1. **Брама старту** — показати план (10-15 кроків) → чекати «ок» власника → тоді виконувати.
2. **Брама деплою** — між брамами лише **локальні коміти, БЕЗ push**. Публікація тільки коли
   власник каже слово-дозвіл на реліз. Хук `flow-push-lock.js` блокує push, поки план активний.

## Стани кроків
🟢 **GO** — виконую (читання/код/тест/локальний коміт)
🟡 **ТВОЯ ЧЕРГА** — потрібен живий тест або ввід власника
🔴 **СТОП** — питаю спершу: архітектура · зміна схеми даних · нові ключі сховища · незворотні
дії · конфлікт із роадмапом

## Видимість
Кожне повідомлення з `[/flow N/M]`. Перед кроком — одне речення. Після — що зроблено + хеш
коміту + наступний крок. Пульс: `🟢 [4/11] Парсер дати · abc1234 · далі: 5 — фільтр`

## Сторож контексту 75%
Хук `flow-context-guard.sh` блокує тихий вихід при ≥75%: дозаповнити «Де зупинились»,
Статус: `paused`, гучне повідомлення власнику. Новий чат → `/flow` → продовжить.

---

## Фаза 0: Вхід
1. Прочитати «Режим глибокої роботи».
2. `git branch --show-current` — працюю на робочій гілці, НЕ в бойовій. Глянути останні коміти.
3. `FLOW_PLAN.md` зі статусом `active`/`paused` → режим **ПРОДОВЖЕННЯ** (прочитати весь файл, Фаза 2).
   Інакше → **НОВИЙ** (прочитати SESSION_STATE + TASKS).

## Фаза 1: Планування (тільки НОВИЙ)
1. Прочитати **РЕАЛЬНИЙ код** усіх задіяних файлів (не з памʼяті).
2. Нова фіча → короткий ресерч аналогів. Баг → три питання: **корінь / межі / чи не дублюю**.
3. Принципи: найпростіше = найкраще · корінь, не симптом · **мінімум у фічах, максимум у фундаменті**.
4. Скласти 10-15 кроків таблицею у `FLOW_PLAN.md`, кожен 🟢/🟡/🔴. Кроки, що чіпають
   архітектуру/схему/сховище → **одразу 🔴**.
5. Статус: `active` (вмикає push-замок).
6. Оцінка обсягу: N кроків × ~35K токенів ≈ X% вікна. **>60% — запропонувати розбити на два потоки.**
→ **БРАМА СТАРТУ:** показати план (≤20 рядків) + оцінку → «Стартуємо? (так / зміни крок N /
розбити / скасувати)». Чекати «ок».

## Фаза 2: Потік (цикл на крок)
1. Прочитати код у точці зміни (файл міг змінитись).
2. Виконати: файли >250 рядків → каркас + правки частинами; зміни в коді → підняти версію кешу.
3. Перевірити: `node --check`.
4. **Локальний коміт (БЕЗ push):** `feat(<зона>): крок N — <опис> [flow]`
5. Оновити `FLOW_PLAN.md`: крок ✅ + хеш + «Де зупинились».
6. 🔴/🟡 крок → стоп, спитати, чекати.
   **Дві невдалі спроби фіксу поспіль → пре-мортем → стоп** (не латка на латці).

## Фаза 3: Тест-блок
1. `node --check` усіх змінених.
2. `/qa-explore` (рівень за обсягом блоку). Знайдене фіксити ДО реліз-нотаток.
3. `/audit`.
4. **Реліз-нотатки** у `FLOW_PLAN.md`: ЩО ЗМІНИЛОСЬ / ЩО МОЖЕ ЗЛАМАТИСЬ / ЩО ПЕРЕВІРИТИ
   НА ПРИСТРОЇ (≤5 пунктів, лише видимі речі).
5. Показати реліз-нотатки власнику.

## Фаза 4: Брама деплою
1. Перевірки зелені. Червоне = фіксити, не деплоїти.
2. «Блок готовий. Реліз-нотатки вище. Скажи слово-дозвіл — публікую.»
3. Після дозволу: підняти версію кешу → публікація як у `/finish`.
4. Перевірити індикатор версії.

## Фаза 5: Вихід / звіт
1. Підсумок: зроблено (кроки + хеші) · що відкрито · наступний крок.
2. Статус: `done` → перенести план в архів, live-файл скинути в шаблон `idle`.
3. Викликати `/finish`.

## Стоп-слова
«стоп» → Статус `paused`, робота збережена: «🏁 Вийшов на кроці N. `/flow` продовжить.»
«відкат» → стоп + запропонувати повернення до мітки старту (виконати лише з явним «ок»).

## Ніколи в автономії без дозволу
Немає push без слова-дозволу · немає `push --force` · немає `reset --hard` (крім відкату з «ок») ·
немає злиття в бойову · немає нових ключів сховища / зміни схеми даних без 🔴-стопу ·
**немає змін самих правил і `CLAUDE.md`**.

## Не дублювати інші скіли
UI → `/mockup` · баг → `/fix` · браузер-тест → `/qa-explore` · кінець → `/finish`.
