## 1. Що це таке

`BOOTSTRAP_PROMPT.md` — це **система роботи**, знята з живого проєкту (медіа-платформа `CSTL NEWS`,
власник Вова). Не бібліотека, не фреймворк, не код. Це набір правил поведінки для тебе:
як спілкуватись, коли можна чіпати код, як вести документацію, як публікувати, як перевіряти себе.

**Це НЕ теорія.** Кожне правило там оплачене реальною помилкою: зламаним деплоєм (публікацією),
стертим фіксом, регресом на телефоні власника. У документі майже кожне правило має рядок «чому» —
не викидай його, він і є цінністю.

**Розмір:** 21 розділ, ~800 рядків. Складається з:

| Розділ | Що дає |
|---|---|
| 0 | змінні проєкту (заповнюються один раз) |
| 1-2 | ієрархія правил + розбір 10 конфліктів між джерелами |
| 3-4 | як говорити з власником, коли можна писати код |
| 5-7 | читання/редагування/створення файлів, архітектура, найменування |
| 8-9 | документація, задачі, баги, запити на функціонал |
| 10-11 | git (система контролю версій) і деплой (публікація) |
| 12-13 | перевірки/тести/аудит + економія токенів і контексту |
| 14 | хуки (hooks — автоматичні сторожі Claude Code) |
| 15 | **усі 20 скілів** (skills — інструкції під команду `/назва`) |
| 16-19 | шаблони, best practices, автоматизації, «ніколи не роби» |
| 20-21 | покроковий бутстрап + контрольний чеклист |

## 2. Що фізично з'явиться в репозиторії

Коли власник скаже виконати бутстрап (Розділ 20), ти створиш:

```
CLAUDE.md                      ← сам BOOTSTRAP_PROMPT, перейменований. Читається тобою автоматично
.claudeignore                  ← що не вантажити в контекст (великі й згенеровані файли)
.claude/
  settings.json                ← дозволи (які команди можна без питань) + реєстрація хуків
  commands/*.md                ← скіли: /start /finish /fix /audit /mockup /new-file /qa-explore /flow
                                  + рольові (/copywriting /social /seo-audit /analytics …)
  commands-archived/           ← вимкнені скіли (лежать, але не реєструються)
  hooks/*.js|*.sh              ← 8 сторожів (список нижче)
{DOCS_ROOT}/                   ← папка документації, назву дає власник
  START_HERE.md                ← карта: що читати і в якому порядку
  HOT_RULES.md                 ← 10 найчастіше порушуваних правил
  OWNER_PROFILE.md             ← хто власник, як комунікує
  BUGS.md                      ← відомі баги, формат B-XX
  _ai-tools/
    SESSION_STATE.md           ← поточний стан (головний живий файл)
    TASKS.md                   ← майстер-список задач = джерело істини
    BACKLOG.md                 ← історія й довідка (НЕ джерело істини)
    FLOW_PLAN.md               ← стан напівавтономного потоку
  docs/                        ← ARCHITECTURE · DESIGN_SYSTEM · ROADMAP …
_session-log/                  ← живі журнали сесій, по файлу на день
.github/workflows/             ← автоматизації (деплой, сканер секретів)
```

**Нічого з наявного коду не змінюється.** Бутстрап додає файли правил і документації — і все.

## 3. Що ці 8 хуків реально роблять (щоб ти не злякався блокувань)

| Хук | Коли | Ефект |
|---|---|---|
| перевірка «читав перед правкою» | перед `Edit` | **блокує** правку файлу, який ти не читав у цій сесії |
| нагадування про версію кешу | після правки коду/стилів | пише готове значення з поточним часом |
| перевірка синтаксису | після правки `.js` | одразу проганяє `node --check` |
| попередження про контекст | на кожен запит власника | 35% / 55% / 80% / 90% заповнення |
| git-синк на старті сесії | старт/відновлення | `git fetch` + гучне «локальна гілка відстає» |
| замок публікації | перед `git push` | у напівавтономному режимі **блокує push**, поки власник не сказав слово-дозвіл |
| сторож контексту | спроба завершити хід | при ≥75% не дає тихо вийти без збереження точки зупинки |
| токен-запобіжник | навколо викликів агентів | один дорогий виклик > порогу → пауза сесії до підтвердження власника |

Усі **fail-open** (помилка самого хука не ламає сесію). Блокують лише там, де ціна помилки висока.

## 4. Чого ти НЕ робиш при встановленні

- ❌ Не переносиш код, не копіюєш чужий проєкт, не створюєш архівів.
- ❌ Не змінюєш наявні файли проєкту (крім `.gitignore` — доповнити, і то з дозволу).
- ❌ Не вигадуєш правила «від себе». Правила беруться лише з `BOOTSTRAP_PROMPT.md`.
- ❌ Не переносиш галузеву специфіку донора (новини, автобуси, Олика) — це приклади, не вимоги.
- ❌ Не встановлюєш нічого, поки власник не сказав слово-дозвіл (за замовчуванням — «Роби»).

## 6. Адаптація під чужий проєкт — що можна викидати

| Якщо в проєкті НЕМА | Викинути з правил |
|---|---|
| Service Worker / PWA | усе про `CACHE_NAME` (версію кешу) і офлайн |
| GitHub Pages | розділ деплою замінити на свій, потік «гілка → PR → прод» лишити |
| зовнішньої бази | правила про міграції і «файл ≠ стан живої системи» лишити частково — вони ширші |
| мобільної аудиторії | правила про тап-цілі 44px і жести |
| маркетингу/контенту | рольові скіли `/copywriting`, `/social`, `/seo-audit`, `/analytics` |

**Що не викидається ніколи** (ядро системи):
процес дозволу на код · читання перед правкою · один крок за раз · не губити попередні фікси ·
не писати «готово» до перевірки · живий журнал сесії · один майстер-список задач ·
двогілковий потік · «не чіпай те, про що не просили» · «мірку перевіряти так само, як код».

## 7. Як зрозуміти, що встановилось правильно

Через одну робочу сесію мають виконуватись усі пункти:

- [ ] `CLAUDE.md` у корені — єдине повне джерело правил, дублів немає
- [ ] `/start` дає стандартну першу відповідь: гілка + стан + топ-3 задачі + критичні баги
- [ ] `/finish` доводить роботу до прода і видає підсумок одним блоком для копіювання
- [ ] правка файлу без читання — блокується
- [ ] стан оновлюється після кожної зміни, журнал ведеться по ходу (а не наприкінці з пам'яті)
- [ ] у кожній твоїй відповіді: пояснення термінів у дужках, правильний рід, стислість без втрати змісту

## 8. Одне речення, якщо ніколи це не читати

> Ти встановлюєш не інструмент, а **дисципліну**: не чіпати код без дозволу, не правити
> непрочитане, не звітувати про неперевірене — і записувати причину кожного рішення туди,
> де її знайде наступна сесія.
