## 2. 🔴 ПЕРЕВИПУСТИТИ СЕКРЕТ PUSH

**Що не так.** Секрет, яким Edge Functions доводять себе базі, лежав **відкритим
текстом у тілі завдання розкладу** (`cron.job`). Будь-хто, хто мав доступ до бази
з правами на читання розкладу, бачив його рядком.

**Чому не зробив сам.** Новий ключ — це 🔴-стоп; і записати його в репозиторій я
не маю права взагалі (репозиторій **публічний**).

**Що робити.** Згенерувати новий секрет, покласти його в `app_secrets`, оновити
завдання розкладу, які його передають. 🛑 У репозиторій не писати НІКОЛИ.
Скажи, коли будеш робити — підготую точний блок SQL під твої назви завдань.

## 5. 🟡 ПОСТАВИТИ ОДИН СЕКРЕТ — І ФУНКЦІЇ ПЕРЕСТАНУТЬ РОЗХОДИТИСЬ

**Що не так.** Після деплою я звірив живий код усіх 8 функцій із репозиторієм
побайтово — і **чотири з восьми розійшлись**. Самі розбіжності нешкідливі
(вкорочені роздільники з рисок у коментарях, загублений апостроф, і один рядок
`json()` із переставленими ключами `headers`, який нічого не міняє). Але важливий
не зміст, а факт: **прод і репозиторій можуть розійтись непомітно**. Наступного
разу розійдеться не коментар.

**Корінь не в неуважності, а в шляху.** Деплой функцій ішов через мене, тобто
текст функції проходив через переписування. Єдиний спосіб зробити прод точною
копією репозиторію — везти файли **інструментом**, а не текстом.

**Що я вже зробив за тебе.** Завів `supabase/config.toml` (із `verify_jwt` кожної
функції, знятим із живого прода) і воркфлов
`.github/workflows/functions-deploy.yml`, який везе всі функції офіційним CLI
щоразу, коли міняється тека `supabase/functions/`.

**Що робити (дві хвилини).**
1. Supabase → Account → Access Tokens → **Generate new token**, скопіювати.
2. GitHub → репозиторій → Settings → Secrets and variables → Actions →
   **New repository secret**, імʼя `SUPABASE_ACCESS_TOKEN`, значення — токен.
3. Actions → «Deploy Supabase Edge Functions» → Run workflow.

⚠️ **До цього перший прогін буде ЧЕРВОНИЙ, і це навмисно.** Він падає з рядком
«Немає секрету SUPABASE_ACCESS_TOKEN». Мовчазний успіх на неробочому деплої
гірший за червоний хрестик — рівно так `publish-now` півдня писав «1-2 хв», не
маючи секрету (урок 28.08).
