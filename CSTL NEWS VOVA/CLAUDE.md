## ВСІ ПРАВИЛА

### Процес роботи
- **БЕЗ "Роби" від Вови — не змінювати код.** Вова каже "Роби" — і тільки тоді.
- **ОДИН баг за раз.** Після виправлення — запропонуй наступний.
- **ЧИТАЙ код перед змінами.** Ніколи "на пам'ять". При кожній зміні — перевір що попередні виправлення збережені.
- **НІКОЛИ не створювати правила самостійно.** Завжди спочатку запитати Вову.
- **Сперечайся** — вказуй на слабкі місця ідеї, не погоджуйся заради ввічливості.
- **Пропонуй кращі рішення** — Claude краще знає технічні можливості. Не просто виконуй, а активно пропонуй.
- **Mockup перед кодом** — якщо задача про UI, показати макет і отримати підтвердження.
- **Пояснюй свої дії** — після кожної дії коротко: що зробив, для чого, як це працює.
- **КОРОТКІ ВІДПОВІДІ.** Середні або менше середнього. По пунктах, зрозумілою мовою. Без розгорнутих абзаців і таблиць на пів екрану. Якщо є вибір між довгим і коротким — завжди коротше. Деталі — тільки на запит "розкажи детальніше".
- **Контент для пересилання — ЗАВЖДИ готовим блоком для копіювання.** Якщо генерую щось, що власник комусь перешле або кудись вставить (лист редактору/партнеру, повідомлення Вові, кроки-інструкція, текст оголошення тощо) — одразу давати це одним `code block` (моноширинний блок, який копіюється однією кнопкою), без пояснень усередині блока. Не чекати окремого прохання «дай блоком».

### Якість виконання
- **CSS/layout — описати результат перед пушем:** приклад "зовнішній елемент (outer — той що видно зсередини) 360px, padding (внутрішній відступ) 20px з кожного боку → вміст буде 360−40 = 320px". Це дає Вові розуміння що саме пушиш. Якщо не можу описати — не пушу. Для модалок — перечитай `docs/DESIGN_SYSTEM.md` → секція "Помилки які були зроблені".
- **Якщо перша спроба не спрацювала — СТОП.** Перечитати код, зрозуміти ЧОМУ не спрацювало, тільки тоді наступна спроба.
- **Не губи попередні фікси** — при кожній зміні перевіряти що попередні виправлення збережені.
- **Перевіряй синтаксис** — після JS змін: `node --check файл.js`.

### Деплой (публікація на сервер — підхід А+ + двогілковий потік)

**Двогілковий потік (branching workflow):**

```
Робоча гілка (claude/start-session-XXX)
    ↓ розробка, експерименти, обговорення, коміти
    ↓
Вова перевірив і сказав "Роби /finish"
    ↓
Скіл /finish:
  1. CACHE_NAME у sw.js (якщо змінювався код)
  2. node --check для зміненого JS
  3. Оновити SESSION_STATE_VOVA.md
  4. git push робочої гілки
  5. mcp__github__create_pull_request → mcp__github__merge_pull_request (squash)
    ↓
main отримує мердж-коміт
    ↓
.github/workflows/deploy.yml запускається автоматично:
  1. npm install (встановлює esbuild — збирач коду)
  2. node build.js (збирає bundle.js зі src/)
  3. sed замінює плейсхолдер лічильника версії у index.html на свіжий час Києва
  4. actions/upload-pages-artifact@v3 (завантажує весь проект як artifact — пакунок файлів)
  5. actions/deploy-pages@v4 (деплоїть artifact прямо на GitHub Pages)
    ↓
Сайт оновлюється через 1-3 хв
```

**Правило гілок:**
- **Робоча гілка** — все недороблене, експерименти, що ще обговорюємо.
- **`main`** — тільки готові узгоджені зміни. Мерджимо через `/finish` коли власник сказав "готово, публікуй".
- **Не пушити в `main` напряму** з робочої сесії — тільки через PR через `/finish`.

## Система деплою (А+)

**Флоу:** пушиш у `main` → `.github/workflows/deploy.yml` автоматично:
1. `npm install` (встановлює esbuild)
2. `node build.js` (збирає `bundle.js` зі `src/`)
3. `sed` замінює плейсхолдер у `index.html` на `v{run_number} · DD.MM HH:MM` (час Києва)
4. `actions/upload-pages-artifact@v3` (завантажує весь проект як artifact)
5. `actions/deploy-pages@v4` (публікує artifact на GitHub Pages)

**URL сайту:** `https://volodymyr221.github.io/CSTL_NEWS/`

**Лічильник версії** — маленький сірий текст **по центру шапки** (`.deploy-stamp`, `style/base.css`). Формат: `v{N} · DD.MM HH:MM`. Якщо після пушу число не змінилось — деплой не пройшов.

**Запуск тільки при пуші у `main`**, але можна вручну: `github.com/Volodymyr221/CSTL_NEWS/actions → Deploy CSTL NEWS → Run workflow`.

**Вимога (одноразово):** у `Settings → Pages → Source` мусить стояти "GitHub Actions" (не "Deploy from a branch").
