**Запит Вови:** *«я хочу завантажити пост про Олику, мені пише що пост містить заборонені

бо це вже занадто трохи»*.

**Де тост:** `src/tabs/feed.js:2163` — `containsProfanity(text)` у композері поста «Стрічки».

**Знайдено (не на око — прогнав справжній `src/core/utils.js` у node зі стабами браузера,
скрипти у скретчпаді `diag.mjs` / `false.mjs`):**
- `containsProfanity(post) = true`, `looksLikeSpam(post) = false`.
- Спрацьовує **крок 2 «squashed» прохід** (`utils.js:350-351`): він прибирає з тексту ВСЕ,
  крім літер (пробіли, коми, переноси), і шукає стеми як **підрядок** у злитому тексті.
- Точне місце в пості: `...заходи та ро[блят]ь усе, щоб сюди...` — слово **«роблять»**
  саме по собі містить `блят`. Жодного матюка в тексті нема.

**Масштаб — НЕ один пост.** Тест 21 звичайної української фрази → **15 заблоковано**:
| Фраза | Що зловило |
|---|---|
| роблять / зроблять / люблять | `блят` усередині слова |
| свій обовʼязок · який обрав · твій образ · стій обережно · тримай оборону · хай обирає | склейка `…й` + `об…` = `йоб` |
| під орудою · під ореолом | склейка = `підор` |
| купи здоровя | склейка = `пизд` |

Той самий фільтр стоїть не лише на постах: коментарі «Стрічки» (`feed.js:1437,1467`),
Дошка (`board-chat.js:348,372`), обговорення (`board-discussions.js:392,836`),
оголошення (`community-modal.js:396`). Тобто слово «роблять» не проходило **ніде**.

**⚠️ Дзеркало в базі теж хибне:** `scripts/supabase_antispam_shared.sql` крок 4
(`regexp_replace(cyr,'[^а-яіїєґa-z]','','g') ~ '(…|йоб|бляд|блят|…)'`) — та сама механіка
1-в-1. Тобто фікс потрібен у ДВОХ місцях, інакше клієнт пропустить, а база мовчки відхилить.
❗ Supabase MCP у цій сесії **не авторизований** → SQL готую, накатує Вова.

**Мій висновок:** різати списки слів не треба — треба полагодити механіку кроку 4.
Він мав ловити рознесене «х у й», а по факту склеює нормальні слова. Виправлення = послаблення
рівно там, де фільтр хибив, без втрати захисту.
