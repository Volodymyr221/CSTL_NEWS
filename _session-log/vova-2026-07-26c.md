### Крок 8 — свайп-закриття листа коментарів: ДВІ спроби, друга влучна

**Вова після PR #660:** «Коли я закриваю свайпом модальку коментарів, вона не звертається

**Спроба 1 (PR #663) — знайшов РЕАЛЬНУ проблему, але НЕ ту, що давала симптом.**
Свайп закриває через `translateY(100%)` = 100% ВЛАСНОЇ висоти. Одночасно мій вчорашній
обробник `blur` повертав лист із ~496px у 692px — з переходом. Висота росла саме тоді,
коли лист мав їхати вниз → ціль тікала. Фікс: `beginClose()` морозить висоту + прапорець
`closing` глушить `blur`. Стенд: розкид висоти 196px → 0px.
**Вова: «Всеодно пропадає якось, не видно що вона згортається до низу».**

**СТОП і пре-мортем** (правило двох спроб — не робити латку на латку).
Перечитав CSS замість гадання. Знайшов:
`.fd-sheet-back { opacity: 0; transition: opacity .2s }` + `.open { opacity: 1 }`.
На початку закриття виконувалось `back.classList.remove('open')` — і гасило УВЕСЬ контейнер
РАЗОМ ІЗ ЛИСТОМ. Лист їхав вниз, але зникав раніше, ніж доїжджав.

**Замір, який усе вирішив** (стенд `visible.mjs`, видима непрозорість по кадрах):

НОВА: 1 усю дорогу.

**Чому безпечно прибрати:** затемнення гасне ІНШИМ механізмом — `fade.settle()` у режимі `'bg'`
міняє альфу КОЛЬОРУ фону, а не `opacity`. У `sheet-motion.js` прямо написано «Гасити
прозорість не можна — разом із фоном загас би й аркуш». Тобто `remove('open')` був ДРУГИМ,
зайвим згасанням. Опція `keepVisibleOnDismiss` — лише для листа коментарів (PR #664).
