# 003 — Закрити рух на `:hover` від дотику (фальшивий hover залишає картку збільшеною)

- **Status**: ✅ DONE (15.08.2026, гілка `claude/startuem-s3yr33`)
- **Commit**: 34143baf
- **Severity**: MEDIUM
- **Category**: 6 (Accessibility)
- **Estimated scope**: 1 файл (`style/board.css`), ~4 рядки

## Problem

`style/board.css:88`:

```css
/* style/board.css:88 — поточний код */
.cm-board-note:hover { transform: rotate(0deg) scale(1.02); z-index: 5; }
```

Правило не має жодного гейту на тип вказівника. На сенсорному екрані браузер після
тапу стріляє **фальшивим `:hover`** і тримає його, доки людина не торкнеться іншого
місця. Наслідок: картка після тапу **залишається збільшеною на 2% і піднятою над
сусідами** (`z-index: 5`) — виглядає як застрягла.

Наш застосунок — мобільна PWA; сенсорний екран тут не крайній випадок, а основний.

🔑 **Де це живе.** У самій Дошці рух уже скасовано окремим правилом
(`style/board.css:2461` — `#board-content .bd-ad:hover { transform: none; }`), тому
на вкладці «Дошка» вади не видно. Але клас `.cm-board-note` носять ще три поверхні
**поза** `#board-content` (див. `src/tabs/board.js:280`):
віджет Дошки на Громаді · зум-модалка картки · прев'ю подачі оголошення.
Саме там правило :88 і працює наживо.

⚠️ У проєкті **немає жодного** `@media (hover: hover)` — цей план заводить конвенцію,
а не наслідує наявну.

## Target

```css
/* target — style/board.css:88 */
/* 🔴 Гейт обовʼязковий: на дотику браузер стріляє фальшивим :hover і тримає його
   після тапу — картка залишалась би збільшеною. `pointer: fine` відсікає палець,
   `hover: hover` — пристрої, що взагалі не вміють наведення. */
@media (hover: hover) and (pointer: fine) {
  .cm-board-note:hover { transform: rotate(0deg) scale(1.02); z-index: 5; }
}
```

Значення руху **не змінюються** — змінюється тільки те, на яких пристроях воно діє.

## Repo conventions to follow

- Стилі зони Дошки живуть у `style/board.css`, підключеному `@import` одразу після
  `community.css`. 🔴 **Порядок `@import` не чіпати** — на ньому тримається каскад
  (`CLAUDE.md`, рядок про `style/board.css`).
- Пояснення «чому саме так» пишуться коментарем **над** правилом — так зроблено в
  усьому файлі. Взірець: `style/board.css:2461` і сусідні блоки.
- Медіа-запит ставиться на місці наявного правила, не переноситься в кінець файлу:
  відносний порядок правил Дошки збережено байт-у-байт і його бережуть навмисно.

## Steps

1. `style/board.css:88` — обгорнути наявне правило в
   `@media (hover: hover) and (pointer: fine) { … }`, **не міняючи** значень
   `transform` і `z-index`.
2. Над медіа-запитом додати коментар із блоку «Target» (українською, як решта файлу).
3. **Не чіпати** `style/board.css:2461` (`#board-content .bd-ad:hover { transform: none }`).
   Воно лишається: скасовує рух саме у списку Дошки, і це окреме рішення.
4. Перевірити `grep -c "hover: hover" style/board.css` → має стати **1**.

## Boundaries

- НЕ шукати й НЕ гейтити інші `:hover` — сweep показав, що рух на наведенні у
  проєкті рівно один. Правила з `background`/`color`/`border` на `:hover` **не
  чіпати**: зміна кольору від фальшивого hover нешкідлива, а їх у файлі десятки.
- НЕ міняти значення `scale(1.02)`, `rotate(0deg)`, `z-index: 5`.
- НЕ переносити правило в інше місце файлу і НЕ чіпати `@import` у `style.css`.
- Нових залежностей не додавати.
- Розбіжність із наведеним кодом → зупинись і доповідай.
