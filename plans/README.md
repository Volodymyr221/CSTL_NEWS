## 🔑 Головне з аудиту

**Попередній прохід (12.08, PR #906) дивився CSS і не дивився JS.** У застосунку
**43 місця**, де рух задається з JavaScript (`element.style.transition = …`), і
жодне з них не бере токени кривих зі `style/base.css`. Саме там і лишились вади,
які в CSS уже виправлені — включно з тією самою кривою `ease-in`, про яку в
`style/buses.css` лежить коментар «прибрано, бо помилка».

## Рекомендований порядок

**002 → 003 → 001.** Від найдешевшого до найдорожчого:

- **002** — два рядки, нульовий ризик, закриває пряме повторення вже визнаної помилки.
- **003** — чотири рядки, значення руху не змінюються взагалі, лише гейт пристрою.
- **001** — найбільший виграш і найбільший ризик: видаляє ~45 рядків власного жесту.
  Робити **останнім** і обовʼязково з живою перевіркою на iPhone: у застосунку **три
  різні механізми закриття** (`#article-modal` · аркуші `core/modal.js` · шари
  `core/layers.js`), і плутати їх не можна.

## Залежності

Планы незалежні один від одного — можна брати будь-який окремо. Але 001 і 002
чіпають одну тему (криві в JS), тож після обох варто одним прогоном перевірити:

```
grep -rn "cubic-bezier" src/ | grep -v "SHEET_EASE\|--ease"
```
