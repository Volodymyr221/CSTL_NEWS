# Стенди CSTL — як ними користуватись

**Одна команда на все:**

```
npm test
```

Один стенд: `node tests/toast.mjs` · кілька: `npm test -- toast pin`

---

## Навіщо це і чому саме тут

Стенд — це маленька програма, яка **вимірює** поведінку застосунку числами: відкриває
справжній HTML із справжнім CSS у браузері (або виконує справжній код із `src/`) і
перевіряє конкретні значення. Не «здається, працює», а «плашка 359px, тексту треба
359px, за екран вилазить 0px».

⚠️ **Чому вони переїхали в репозиторій (27.07).** Раніше стенди жили в тимчасовій теці
сесії. У документах проєкту досі згадуються сторожі `kb-guard.test.js` і
`kb-tapinput.test.js` — але їх **ніколи не було в git**: вони зникли разом із сесією, а
посилання лишились. Тобто перевірка, яку колись написали, не захищала вже нічого.
Тепер стенди в репозиторії й запускаються однією командою.

## 🔴 Головне правило: мірку перевіряти так само, як код

За одну сесію перевірка збрехала **шість** разів і щоразу мало не дала хибний висновок:

- міряла `scrollWidth` там, де вміст **неможливо посунути** — і кричала про переповнення;
- давала **324 «розбіжності» на НЕЗМІНЕНОМУ коді** — це були живі дані (стрічка
  оголошень крутиться, смужка автобуса повзе);
- завалила **еталон**, який Вова прийняв як добрий, — бо рахувала кадри вже після
  кінця анімації;
- міряла **власне** тло елемента замість того, що видно оку;
- регулярка всередині шаблонного рядка втратила зворотні слеші й не збігалась **ніколи**;
- перевіряла **форму запису** замість наслідку — і пропустила справжній баг.

**Три правила з цього:**

1. перед порівнянням двох станів спершу зміряй, що дає порівняння стану **з самим
   собою**. Шумовий поріг має бути **0** — інакше порівнювати нема сенсу;
2. критерій має міряти **те, що побачить Вова**, а не те, що зручно перевірити;
3. якщо перевірка «завалила» те, що Вова вже прийняв як добре — **першою підозрюваною
   є перевірка**, а не код.

## Як додати новий стенд

1. Створи `tests/<назва>.mjs`.
2. Візьми з `./_lib.mjs` те, що треба: `ROOT`, `projectFile()`, `launch()`, `serve()`,
   `blockExternal()`, `reporter()`. **Жодних абсолютних шляхів** — вони і вбили
   попередні сторожі.
3. Останній рядок виводу — `✅ N/M перевірок пройдено`, вихід `process.exit(0|1)`.
   Саме за цим рядком `run.mjs` збирає підсумок.
4. Якщо потрібен живий застосунок — `const { url, stop } = await serve()`; сервер
   підніметься сам на вільному порту.
5. Стенд має **ганяти справжній код**, а не його копію: `projectFile()` читає файл
   із `src/`, за потреби витягуючи потрібний блок. Копія перевіряла б саму себе.

Багато стендів уміють прогін по версіях коду — зручно, щоб довести, що баг був:

```
CSS_REV=<коміт> node tests/toast.mjs
```
